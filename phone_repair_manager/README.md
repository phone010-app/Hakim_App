# تطبيق إدارة محل صيانة الهواتف 📱🔧

تطبيق Flutter كامل لإدارة عمليات صيانة الهواتف، حساب الأرباح والعربون،
متابعة ديون الموردين والزبائن، أجور التوصيل، والغلق الأسبوعي مع أرشفة
التقارير وربطها بـ Google Sheets، وحماية بالكامل برمز PIN.

---

## 1) محتوى المشروع

```
phone_repair_manager/
├── pubspec.yaml                  # المكتبات المطلوبة
├── lib/
│   ├── main.dart                 # نقطة الانطلاق + شاشة قفل PIN
│   ├── models/                   # نماذج البيانات (RepairOrder, SupplierDebt...)
│   ├── services/                 # قاعدة البيانات المحلية + خدمة PIN + خدمة جوجل شيت
│   ├── providers/                # AppState (يربط الشاشات بالبيانات)
│   ├── screens/                  # الحاسبة / الديون / الطلبات / الأرشيف / الإعدادات
│   ├── widgets/                  # عناصر واجهة قابلة لإعادة الاستخدام
│   └── utils/                    # الثيم + دوال تنسيق الأرقام والتواريخ
└── google_apps_script/
    └── Code.gs                   # سكريبت الربط مع Google Sheets
```

جميع البيانات تُحفظ **محلياً على الهاتف** أولاً (قاعدة بيانات SQLite عبر
`sqflite`)، لذلك يعمل التطبيق حتى بدون إنترنت. الربط بـ Google Sheets هو
نسخة احتياطية تلقائية فقط، وإن فشل الاتصال لا يتوقف التطبيق أبداً.

## 2) تجهيز بيئة Flutter (مرة واحدة على حاسوبك)

1. ثبّت Flutter SDK من الموقع الرسمي: https://docs.flutter.dev/get-started/install
2. ثبّت Android Studio (يوفر Android SDK + محاكي أندرويد).
3. تأكد من صحة التثبيت بتنفيذ الأمر التالي في الطرفية (Terminal):
   ```
   flutter doctor
   ```
   وقم بحل أي مشكلة يشير إليها (خصوصاً ترخيص Android SDK: `flutter doctor --android-licenses`).

---

## 3) تشغيل المشروع

> ⚠️ **مهم جداً**: هذا المجلد يحتوي على كود Flutter المصدري فقط (`lib/`
> و `pubspec.yaml`) وليس فيه مجلدات `android/` و `ios/` الخاصة بالمنصة.
> يجب توليدها مرة واحدة أولاً بالأمر التالي.

1. افتح طرفية (Terminal) داخل مجلد `phone_repair_manager` ونفّذ:
   ```
   flutter create .
   ```
   هذا الأمر يضيف مجلدات `android/` و `ios/` وباقي ملفات المنصة **دون
   المساس بمجلد `lib/`** الذي كتبناه لك (لأن الأمر يدمج فقط الملفات
   الناقصة). بعده افتح `pubspec.yaml` وتأكد أن اسم الحزمة ما زال
   `phone_repair_manager` وأن قسم `dependencies` كما هو في الملف الأصلي
   (لن يُغيّره الأمر عادة، لكن تحقق للاطمئنان).
2. افتح المجلد في VS Code أو Android Studio.
3. نزّل المكتبات:
   ```
   flutter pub get
   ```
4. وصّل هاتف أندرويد حقيقي بكابل USB وفعّل عليه "خيارات المطور" ثم
   "تصحيح USB" (USB Debugging)، أو شغّل محاكي أندرويد من Android Studio.
5. تحقق أن الجهاز ظاهر:
   ```
   flutter devices
   ```
6. شغّل التطبيق:
   ```
   flutter run
   ```

### لإنشاء ملف APK لتثبيته مباشرة على الهاتف (بدون كابل لاحقاً)
```
flutter build apk --release
```
سيجد الملف الناتج في:
`build/app/outputs/flutter-apk/app-release.apk`
انقله إلى الهاتف وثبّته (فعّل "السماح بالتثبيت من مصادر غير معروفة" إن طُلب ذلك).

## 4) بناء APK تلقائياً عبر GitHub (بدون تثبيت Flutter على حاسوبك) 🤖

إذا لم ترغب بتثبيت Flutter على جهازك، يمكنك رفع الكود مرة واحدة فقط إلى
حساب GitHub مجاني، وسيقوم GitHub تلقائياً ببناء ملف APK جاهز للتثبيت في
كل مرة تُعدّل فيها الكود — عبر ملف `.github/workflows/build.yml` المُرفق
في المشروع (خدمة GitHub Actions، تعمل مجاناً للمستودعات العامة والخاصة
ضمن حد شهري سخي يكفي هذا الاستخدام بسهولة).

### أ) إنشاء حساب ومستودع (Repository) على GitHub
1. أنشئ حساباً مجانياً على https://github.com إن لم يكن لديك.
2. اضغط **+ (أعلى يمين الصفحة) ← New repository**.
3. اختر اسماً مثل `phone-repair-manager`، واتركه **Public** أو **Private**
   (كلاهما يدعم Actions مجاناً)، ثم **Create repository**.

### ب) رفع الكود إلى المستودع
أسهل طريقة بدون سطر أوامر: من صفحة المستودع الفارغ اضغط
**"uploading an existing file"**، ثم اسحب مجلد `phone_repair_manager`
بالكامل (أو فك ضغط الـ zip وارفع كل الملفات والمجلدات) واضغط
**Commit changes**.

أو عبر سطر الأوامر (Git) إن كان مثبتاً لديك:
```
cd phone_repair_manager
git init
git add .
git commit -m "أول رفعة للمشروع"
git branch -M main
git remote add origin https://github.com/USERNAME/phone-repair-manager.git
git push -u origin main
```
(استبدل `USERNAME` باسم حسابك واسم المستودع الذي اخترته).

> ملاحظة: ملف `.gitignore` المُرفق يستثني تلقائياً الملفات المؤقتة الثقيلة
> (مثل `build/`) فلا داعي للقلق من رفعها.

### ج) متابعة عملية البناء
1. بمجرد اكتمال الرفع، افتح تبويب **Actions** أعلى صفحة المستودع.
2. ستجد عملية تشغيل باسم "بناء APK للتطبيق" بدأت تلقائياً — اضغط عليها
   لمتابعة تقدمها (تستغرق عادة 5-10 دقائق للمرة الأولى).
3. عند اكتمالها بعلامة ✅ خضراء، انزل لأسفل الصفحة إلى قسم **Artifacts**
   واضغط على **app-release-apk** لتنزيل ملف APK جاهزاً مباشرة.
4. بديلاً، افتح تبويب **Releases** في المستودع (على اليمين) — ستجد
   إصداراً جديداً بكل عملية بناء، وبداخله رابط تحميل مباشر لملف APK يمكن
   نسخه وفتحه من متصفح الهاتف مباشرة لتثبيت التطبيق دون الحاجة لحاسوب.

### د) في كل مرة تُعدّل فيها الكود مستقبلاً
فقط ارفع (push أو "Upload files" مجدداً) التعديل إلى الفرع `main`،
وسيبني GitHub نسخة APK جديدة تلقائياً من جديد — دون أي إعداد إضافي.

## 5) إعداد الربط مع Google Sheets (خطوة بخطوة)

### أ) إنشاء جدول Google Sheets جديد
1. افتح https://sheets.google.com وأنشئ جدولاً (Spreadsheet) جديداً فارغاً.
2. سمّه مثلاً: **محل الصيانة - قاعدة البيانات**.

### ب) إضافة سكريبت الربط
1. من داخل الجدول، اذهب إلى القائمة: **الإضافات (Extensions) ← Apps Script**.
2. سيفتح محرر Apps Script بملف افتراضي اسمه `Code.gs` — احذف محتواه بالكامل.
3. افتح ملف `google_apps_script/Code.gs` الموجود في هذا المشروع، انسخ كل
   محتواه، والصقه في محرر Apps Script.
4. احفظ المشروع (أيقونة الحفظ أو Ctrl+S)، وسمّه مثلاً "ربط تطبيق الصيانة".

### ج) نشر السكريبت كـ Web App
1. من محرر Apps Script، اضغط الزر الأزرق **نشر (Deploy) ← نشر جديد (New deployment)**.
2. اضغط على أيقونة الترس ⚙️ بجانب "اختر النوع" واختر **Web app**.
3. في الإعدادات:
   - **Execute as**: حسابي (Me)
   - **Who has access**: Anyone (أي شخص) — هذا ضروري ليستطيع التطبيق
     الاتصال بالسكريبت من الهاتف.
4. اضغط **نشر (Deploy)**.
5. سيطلب منك Google تسجيل الدخول ثم الموافقة على الصلاحيات (Authorize
   access) — اختر حسابك، وإذا ظهرت رسالة "Google hasn't verified this
   app"، اضغط **Advanced/متقدم ← الانتقال إلى (اسم المشروع) — غير آمن**؛
   هذا طبيعي لأنه سكريبت خاص بك أنت فقط.
6. بعد النشر، سيعطيك Google رابطاً ينتهي بـ `/exec` يشبه:
   ```
   https://script.google.com/macros/s/AKfycb.../exec
   ```
   **انسخ هذا الرابط بالكامل.**

### د) ربط الرابط بالتطبيق
1. افتح التطبيق على الهاتف.
2. اذهب إلى تبويب **"الإعدادات"** (آخر أيقونة في الشريط السفلي).
3. الصق الرابط في خانة "رابط Web App" ثم اضغط **"حفظ الرابط"**.
4. جرّب حفظ أي عملية صيانة من "الحاسبة" — بعد ثوانٍ افتح جدول Google
   Sheets وستجد ورقة جديدة اسمها **"العمليات"** أُنشئت تلقائياً وبها
   الصف الذي أضفته.

> ملاحظة: السكريبت ينشئ تلقائياً 5 أوراق حسب الحاجة: العمليات، التقارير
> الأسبوعية، ديون الموردين، ديون الزبائن اليدوية، أجور التوصيل — لا داعي
> لإنشاء أي ورقة يدوياً.

### هـ) تحديث السكريبت لاحقاً
إذا عدّلت `Code.gs` مستقبلاً، يجب نشر **إصدار جديد** حتى تُطبَّق
التعديلات: **نشر ← إدارة عمليات النشر (Manage deployments) ← تعديل
(القلم) ← إصدار جديد (New version) ← نشر**. الرابط `/exec` يبقى نفسه
غالباً، لكن تأكد منه في كل مرة.

## 6) نظام حماية PIN 🔒

- عند أول فتح للتطبيق، سيُطلب منك إنشاء رمز مكوّن من 4 أرقام وتأكيده.
- في كل مرة تفتح فيها التطبيق لاحقاً سيُطلب منك إدخال نفس الرمز.
- الرمز يُخزَّن **مشفّراً** على الهاتف فقط (SHA-256) ولا يُرسل لأي مكان.
- لتغيير الرمز: تبويب **"الإعدادات" ← "إعادة تعيين رمز PIN"**، ثم عند
  إعادة فتح التطبيق سيُطلب إنشاء رمز جديد.

## 7) شاشة الأرشيف 🗄️

تبويب **"الأرشيف"** يعرض كل تقارير الغلق الأسبوعي السابقة (محفوظة محلياً
وأيضاً على Google Sheets)، ويمكنك الضغط على أي أسبوع لتوسيع التفاصيل
الكاملة: إجمالي المقبوض، فائدتك، فائدة الشريك، الكريدي المتبقي عند
الزبائن، والديون المتبقية للموردين في تلك اللحظة بالضبط.

## 8) منطق الحسابات (مرجع سريع)

| الحقل | المعادلة |
|---|---|
| المبلغ المتبقي على الزبون | سعر البيع − العربون |
| صافي الفائدة الإجمالية | سعر البيع − سعر الشراء |
| فائدتي / فائدة الشريك | صافي الفائدة الإجمالية ÷ 2 |

- عند الضغط على **"تم التسليم وقبض الثمن كاملاً"**: يصبح "المتبقي" = 0،
  وتدخل العملية رسمياً ضمن أرقام الأسبوع الحالي.
- عند **"غلق جلسة الأعمال الأسبوعية"**: يُحسب تقرير شامل من كل الطلبات
  المُسلَّمة غير المؤرشفة، يُحفظ في الأرشيف ويُرسل لجوجل شيت، ثم تُؤرشف
  هذه الطلبات (تختفي من قائمة "الأسبوع الحالي" لكن تبقى محفوظة). الطلبات
  التي ما زالت "قيد التصليح" أو "بانتظار الزبون" تبقى ظاهرة تلقائياً في
  الأسبوع الجديد لأنها لم تُغلق بعد.
